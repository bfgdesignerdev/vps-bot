# 🍀 Zelenka Cloud Bot (Beta)
Telegram-бот: каждому пользователю создаётся НАСТОЯЩИЙ Docker-контейнер (Linux, 512 МБ ОЗУ, 0.5 CPU, диск 1 ГБ).
Один бесплатный тариф. Docker и опасные команды внутри сервера запрещены.

## Требования
Linux-сервер (VPS) с Docker и Node.js 20+. Cloudflare Workers/Pages для этого НЕ подходят: там нельзя запускать контейнеры.

## Быстрая установка (Ubuntu 22.04)
```
unzip zelenka-cloud-bot-beta.zip && cd zelenka-cloud-bot
sudo bash install.sh
```
Скрипт ставит Docker и Node.js 20, собирает бота и включает автозапуск 24/7 (systemd, сервис zelenka-bot). Токен берётся из .env, если его нет, скрипт спросит.

## Ручной запуск
1. @BotFather -> /newbot -> BOT_TOKEN
2. `cp .env.example .env` и впишите токен
3. `npm i && npm run build`
4. `set -a; . ./.env; set +a; npm start` (первый запуск соберёт образ zelenka-base)
5. Для автозапуска: deploy/zelenka-bot.service (пользователь zelenka в группе docker)

## Безопасность (прочтите)
- Контейнеры: cap-drop ALL, no-new-privileges, не root, pids-limit 128, tmpfs /tmp, лимиты ОЗУ/CPU. Docker-сокет внутрь НЕ пробрасывается.
- Лимит диска 1 ГБ работает при Docker overlay2 на XFS с pquota. Иначе бот создаст контейнер без лимита диска (проверьте df, при необходимости настройте квоты).
- Контейнеры имеют выход в интернет (нужен для pip/git). От абьюза (майнеры, DDoS) защищайтесь: фильтр команд есть, но добавьте egress-ограничения на хосте (iptables/сеть docker).
- Бот имеет доступ к docker (= root на хосте): храните токен в секрете, запускайте отдельным пользователем.
- MAX_SERVERS ограничивает число контейнеров на хосте.

## Что умеет
Приветствие, тариф Free 0 ₽, регистрация (имя, почта), анимация создания, «Мой сервер»: старт/стоп/перезагрузка, статистика, веб-консоль (bash), файлы (просмотр, загрузка, скачивание), удаление сервера.

## Листики и трафик
- При регистрации 15 листиков. Пока сервер запущен, списывается 2 листика в час (проверка раз в минуту). Остановленный сервер бесплатен. При 0 сервер останавливается.
- Трафик: лимит TRAFFIC_LIMIT_GB в сутки (по умолчанию 5). При превышении сеть контейнера отключается до следующего дня (UTC).
- Токен лежит в .env. НЕ публикуйте архив. Если токен где-то светился, перевыпустите его в @BotFather (/revoke).

## 🔑 SSH
Кнопка «🔑 SSH подключиться» в панели сервера: запускает sshd внутри контейнера (порт 2222 проброшен на случайный порт хоста), создаёт новый ключ ed25519 и присылает приватный ключ файлом, адрес, порт и готовую команду `ssh -i zelenka_key -p ПОРТ user@ХОСТ`. Пароля нет, вход только по ключу. Повторное нажатие выпускает новый ключ.
- Для входящих подключений откройте в фаерволе VPS диапазон портов Docker (обычно 32768-60999/tcp) и задайте `SERVER_HOST` в `.env` как публичный IP или домен. Если VPS находится за NAT, провайдер также должен перенаправить этот диапазон на VPS; одного `SERVER_HOST` недостаточно. Автоопределение адреса может не работать на VPS с частным IP или без доступа к `api.ipify.org`.
- Контейнеры, созданные до этой версии, нужно пересоздать (нужен проброс порта). Образ zelenka-base:3 соберётся при первом запуске.
- sshd запускается при нажатии кнопки; после перезагрузки сервера нажмите её снова.
- ⚠️ НИКОМУ не давайте данные SSH-подключения и ключ: кто их получит, получит контроль над сервером.
